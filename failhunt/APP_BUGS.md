# APP_BUGS.md: decoder, app-core, template and language problems found by the failure hunt

Found with the app's own generation loop (`app/js/src/decode_loop.mjs`, arm E, branch phase-5-app at 69b121f), the host copy of the phone core (`molde_core.h`, llama.cpp b12144) and a hand port of the app rules (`app/lib/src/rules.dart`, in `tools/rules.mjs`). Model: r3 Gemma 270M Q4_K_M unless stated. Raw rows: `results/gemma-r3.jsonl` (chain steps carry request, raw model output, app outcome). Tags: **urgent** = a user hits it in normal use and the fix is small; **later** = real but rare, or needs design.

Port caveat: the rules were ported by hand from Dart to JS, line by line. Items 3 to 6 depend on that port being exact; each has a one-line probe in the repro column that an app agent can run in Dart.

## Things checked and found fine

- `noAsk`: with `allowAsk=false` the grammar offers only the app line; 0 asks in 407 creates (the same set with asks allowed: `controls/summary.txt`).
- `namesAThing`: every request in the set that has a real word returned false for `allowAsk`; the three filler-only requests ("make me an app") are not in the set.
- `betterTitle`: never replaced a title in 357 builds; titles are fine.
- Data-safety `evolve`: `refused` was returned 4 times, all for renames; no valid change was refused for another reason.
- `prepareEdit` adds `set` to changed settings: seen working (goal edits show `set`).
- Draft verification (the lossless claim in the header of `molde_core.h`) was NOT tested here; item 1 is the only draft-related fault seen.
